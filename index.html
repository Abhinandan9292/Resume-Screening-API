Workflow

How a candidate moves through Hirely.

Three steps, each handled by the person responsible for it, all writing to the same student record.

  1. PDF Processed
    Detected skillspythonsql
    01 · Student

    Upload a resume

    Hirely extracts the PDF’s text, suggests skills from a defined keyword list and drafts a summary. The student edits both before saving the profile.

  2. python, sql
    pythonsql
    02 · Recruiter

    Search by skill

    Results are ranked by skill-match score, then CGPA. Each profile shows which of the searched skills it lists, so a shortlist is easy to explain.

  3. Seeking
    Placed
    Added to the audit log
    03 · Placement office

    Record the outcome

    Applications reach the recruiter’s inbox for each posting. The placement office marks students as placed and reviews recent activity.

Features

What each workspace includes.

Everything below is part of the product today. Nothing is scored or ranked without showing you what it was based on.

PDF resume parsing

Pre-fills skills and a profile summary from an uploaded resume.

Editable student profiles

CGPA, skills, GitHub link and summary, kept current by the student.

Role publishing

Recruiters post roles with location, experience and compensation.

Applicant inbox

Every application to a recruiter’s roles, filterable by role and exportable to CSV.

Skill-based search

Find active candidates by one or more skills, with matched skills highlighted.

Placement records

Recruiter onboarding, placement status and an audit log for the office.

About match scores. A match score compares the skills a recruiter searches for with the skills listed on a student’s profile. It doesn’t evaluate experience, projects or anything else in the resume, and Hirely presents it as a search aid, not a judgement of the candidate.
